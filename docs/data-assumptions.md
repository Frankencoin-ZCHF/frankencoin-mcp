# Data sources and coverage

| Output | Discovery and cache | Coverage boundary |
| --- | --- | --- |
| Token ledgers, portfolio, transfer filters and CCIP verification | Frankencoin’s `/godeye/tokens` supplies chain, asset and contract. The catalogue is cached for one hour. | A deployment appears when indexed. Separate RPC and DEX Screener adapters use reviewed provider identifiers. Portfolio totals require every indexed balance. |
| CEX markets and peg history | Kraken AssetPairs supplies current online base-ZCHF books, including the CHF candle benchmark. CoinGecko supplies indexed tickers. Market catalogues refresh every ten minutes. | A ticker alone cannot establish executable depth. The historical CHF benchmark uses closed Kraken candles. |
| DEX quotes | Velora’s chain-specific token list supplies counter-token address and decimals, cached for ten minutes. USDC is the default. Pass a listed counter-token contract to select another asset. | A quote requires a valid matching route. The ZCHF, FPS and FCS quantities use their protocol precision. Pool inventory and executable depth have separate sources. |
| Collateral and CHF peers | Frankencoin’s collateral registry supplies membership. CoinGecko Ethereum token-price queries match contracts in batches. Its CHF stablecoin category supplies peer membership. | External price enrichment depends on provider coverage. The CHFAU adapter reads supply and decimals at one Ethereum block. BTC and ETH are the named macro benchmarks. |
| Financial inputs | Positions use reported decimals and terms. Earnings require both profit and loss. Savings totals require every observed module to supply the relevant metric. | Missing inputs produce null. A reported zero remains zero. |
| Editorial content and FCS | GitBook and website repository trees provide selectors through the knowledge index. Named topics and page views remain shortcuts. The full FCS context reads the current mechanics document. App, developer, analytics and insurance operator links or names come from published site content. | Document caches follow the repository default used by this integration (main). Historical audit references identify their reviewed commit. |
| Risk and analytics | Pharos supplies rating pillars. The Xerberus registry supplies Frankencoin-prefixed protocol, organisation and pool entries. Event results identify the feeds queried. | Dune queries, event signatures, Ponder field projections, RPC hosts and reporting adapters are reviewed integrations. New event types need a decoder and pseudonymous output projection. |
| Monitoring policy | PEG_WARNING_BPS and PEG_CRITICAL_BPS default to 50 and 100. PRICE_STALE_SECONDS defaults to 86400. Market responses report peg bands and feed freshness. | Stress at CHF parity is an explicit scenario. A monitoring threshold is an operator policy. |
